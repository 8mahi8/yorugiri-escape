# 夜霧の脱出 — v0.4 潜伏・陽動・チェイス統合設計

Status: **DESIGN BASELINE / NOT IMPLEMENTED**  
Target: BOT相手の1人用ブラウザゲーム。PC、iPhone/iPad（Safari）対応。  
2026-10-12／既存v0.3のゲーム本体は変更しない。

## 0. 北極星
> **見つかる前に状況を読み、見つかった後は地形と情報戦で逃げる。**

潜伏が主役、チェイスが緊張のピーク。プレイヤーが**ハンターの情報（視覚・物音・最後の目撃位置）**を操作するのが独自の楽しさ。
- NG: 走っているだけで必ず逃げ切れる／AIが壁越しに現在位置を透視する／石を投げるだけで必ず安全になる。
- OK: 石で巡回をずらす、物陰から迂回する、目撃された方向と逆へ抜ける、視界遮断後に音を立てると再び見つかりやすい。
- 1人なので発見＝詰みにはせず、被弾後に逃げ直す猶予を残す。

## 1. 現行仕様との境界
- v0.3: マップ1600×1050相当、暗号機5台中3台＋ゲート、HP2、板5枚、草むら7か所、タッチ操作、BOT1体。
- v0.3参考値: 生存者通常175／ハンター追跡169、視界275、視野約140°、記憶約2秒、ダッシュ再使用7秒。
- v0.4ではこのうち追跡速度・捜索処理・入力行動・解読テンポを**セット**で見直す。値は初期チューニング案であり保証値ではない。
- 本番プレイURLは据え置き。コード変更前に仕様とテストケースを固定する。

## 2. ゲームサイクル
1. **偵察** — 視野・巡回・警戒音を観察する。
2. **仕掛ける** — 石を投げる／歩いて回り込む／しゃがんで潜るなどで好条件を作る。
3. **解読** — 進めるほど音とリスクが増す。進捗は中断後も残る。
4. **発見されたらチェイス** — 通常走りだけでは逃げ続けられない。板・角・ダッシュで位置と視線をずらす。
5. **再潜伏** — 視線を切った後に足音を抑え、最後に見た位置から移動し、捜索の裏をかく。
6. 3台解読したら南東ゲートを開けて脱出。単純な安全待機では達成できない。

## 3. プレイヤー行動／初期数値

| 行動 | 初期案 | 意図 |
|---|---|---|
| 通常移動 | 175 u/s | 基準 |
| しゃがみ | 105 u/s、トグル | 遅い代わりに足音が小さい。視界内で突然消えない |
| ダッシュ | 330 u/s、0.9秒、CD9秒 | 一度距離を離す。物音が大きい |
| 石投げ | 所持2個、射程最大300u | 着地点で音を鳴らし別方向の調査を誘う |
| 板 | 使い切り、接触タイミングでスタン | 当てた時だけ大きな利得 |
| 草むら | 既存7か所を利用 | 未発見なら隠れられる。接近・捜索されると危険 |

※ u はワールド座標のゲーム単位。数値は上記マップを前提とした調整初期値。

### しゃがみ
- スマホ：画面右側の「しゃがむ」ボタン（オン/オフ）。PC：C キー（トグル）。
- 移動時の発音量は通常の約25%。ダッシュ中は自動解除。
- **壁越しは見えない**、しゃがみだけで視界内のプレイヤーが透明にはならない。
- 草むらでしゃがんで静止すると発見距離を短縮。ただし至近距離（50u程度）なら探索中のハンターは見つけられる。
- 視認済みのまま草むらに入っても、最後に見えた位置への捜索は続く。

### 石
- スマホ：石ボタン→地面の着地点をタップ（予測位置を表示、キャンセル可）。UI上のタップは投擲扱いしない。PC：Rで照準モード、マウス位置で投げる、Escでキャンセル。
- 着地後の「ガチャッ」という音：音源中心から半径240u（壁で少し減衰する想定）。ハンターは投擲者ではなく**音の場所**だけ知る。
- 投げる瞬間に生存者付近にもごく小さな衣擦れ音（半径70u）を出す。完全な無償陽動にしない。
- **プレイヤーを視認中は追跡が最優先**。目撃直後でも正面追跡中なら音一つで急に向きを変えない。
- 警戒・捜索中は新しい音を調査候補にできる。複数の音があれば新しさ・距離・大きさで評価する。
- 初期2個、上限2個。マップに補充2か所（安全な無限補充は禁止）。音の持続や優先度を含め後で調整。
- 画面外には投げられない／壁を貫通できない／無効な着地点には消費なし。

## 4. ハンターの知覚：事実と推測を分離する
- **VISION**: 前方約150°、300uまで。遮蔽物で遮る。近距離50〜65uでは向きに関係なく視認できるが、遮蔽物は無視しない。視野角の見た目と判定を一致させる。
- **SOUND**: 音の発生座標、強さ、時刻だけを格納。音を聞いただけでは追跡状態へ移らない。通常歩行・しゃがみ・解読・ダッシュ・着石で強さを分ける。
- **LAST_SEEN**: プレイヤーが最後に視認された座標と時刻。視界を失った後はこれを目指す。隠れた生存者の「現在座標」を読まない。
- **MEMORY**: 知識は段階的に弱まる。更新のない座標を永久に追いかけない。
- **NO TELEPATHY**: AIの意思決定は知覚イベント、最後の目撃地点、既知の巡回地点からのみ生成する。障害物の外のプレイヤー座標を毎フレーム追跡先に代入しない。

## 5. ハンターAIの状態機械

| 状態 | 入口 | 挙動 | 出口 |
|---|---|---|---|
| PATROL | 初期／捜索終了 | 暗号機近傍を含む複数ルートを移動。道を向きながら歩く | 視認→CHASE／物音→INVESTIGATE |
| INVESTIGATE | 物音のみ | 音の発生地点へ向かい、到着後に周囲を数秒確認。視界は有効 | 視認→CHASE／有力な新しい音→更新／空振り→PATROL |
| CHASE | 視認 | 生存者を追跡。前方向きを追従。直接見えている間のみ位置情報更新 | 遮蔽→SEARCH／板スタン→STUN |
| SEARCH | 追跡中の視線喪失 | 最終目撃地点へ行き、近隣の2〜3候補地点を検査。およそ6秒の予算、騒音で調整 | 視認→CHASE／音→調査候補更新／時間切れ→PATROL |
| STUN | 板命中／被弾直後の硬直 | 一時停止。追跡位置は凍結、知覚の扱いを明確化 | 硬直後→SEARCH |

- CHASE時の移動速度は**198 u/s**（プレイヤー通常175より上）。PATROL約120、INVESTIGATE約145、SEARCH約150。
- 接近／被弾後は無敵3秒程度＋短い加速、ハンター硬直0.8秒程度を初期案とする。HP2は維持。
- STUN終了後の「再索敵無効」は長くしすぎない。実際に視界に戻ってきたプレイヤーを不自然に無視しない。
- SEARCHは「最終目撃地点に到着したら即帰還」にならないよう、周辺の見通しの良い角や草むら前を複数検査。ただし理由のない隠れ場所を毎回的確に突き止めない。
- 追跡を撒いたかのHUDは内部状態に基づく。SEARCH中は「振り切った」と表示しない。
- 追跡中の石投げは、視線を遮った**後**にだけ有効になり得る（必勝技ではない）。
- 音を連続させて同じ経路を往復させるループを防ぐ。音イベントには再調査抑制タイマーと優先度を設ける。

## 6. 逃走・潜伏の公平性
- **悪手**：何も使わず直線を逃げ続ける→いずれ追いつかれる。
- **良手**：角を曲がる→遮蔽を利用→（必要なら）石を反対へ→しゃがんで別ルートへ→草むらでやり過ごす。
- ハンターはプレイヤーの見失いを即断せず、最後の目撃地点まで来る。これが追跡の緊張感。
- 石の音と生存者の足音が競合した際の「疑う」はAIの限定情報で説明可能であること。読心術的な反応禁止。
- 板は近いだけで自動スタンさせない。ハンターの当たり判定との衝突・使用時刻で判定。早すぎ／遅すぎは足止めのみ。
- スマホ入力での操作ミスをゲーム難易度と混ぜない。ボタン大きめ、長押しとタップの意図を分ける。

## 7. 目的・難易度の土台
- 暗号機は現行の5台から3台解読、ゲートで脱出という目標は維持。
- 解読時間を仮に**10〜12秒/台**へ。中断しても進捗維持。音の発生と捜索の反応を成立させる。
- 難しくする際も「どこにいたか分からないまま見つかる」理不尽は増やさない。
- UI: 警戒ステータス（平常／物音を調査中／追跡中／捜索中）、石残数、しゃがみ状態、ダッシュCD、HP、解読進捗。
- 視野の可視化はテスト中常時、公開版は見やすさを優先し透明度と強度を調整。
- ソロ版に強制的な全体制限時間は設けない。放置しても勝てない目的構造でよい。

## 8. モバイル操作計画
- 左下: 片手ジョイスティック（現行のスティック維持）。
- 右下: 調べる、ダッシュ、しゃがむ、石投げ。親指と重ならない配置を先にテスト。
- 石は**二段階**：ボタンで狙いモード→画面内で着地点を指定。選択中は操作ボタンを押しても誤射しない。キャンセル可能。
- iPhone縦持ち・横持ち・学校iPad横持ちをブラウザ自動テストし、2本指同時入力・解読長押しの解除・ポーズ／再開時入力リセットを確認。
- Safe Area、HUDとボタンの重なり、画面が切れないことを保持する。

## 9. 実装順序（完成条件つき）
1. **基盤＋ログ**：知覚イベント（視認／聴覚）、state遷移、lastSeen、lastHeardを可視化できるデバッグモード。現行版の操作を維持。
2. **基本ステルス**：しゃがみ、足音、草むら、視野判定、INVESTIGATE。隠れるメリットが数値で説明できる。
3. **石の陽動**：照準UI＋投擲判定＋音イベント→調査対象決定。画面外・重複入力・補充濫用も検査。
4. **チェイス／SEARCH**：追跡・視線遮断・調査候補の探索・板スタン・被弾猶予を調整。
5. **マップと解読調整**：解読機周りに最低2つの侵入経路、逃走ルート、陽動先を持たせる。
6. **実機プレイテスト**：初心者と慣れたプレイヤーの両方で理不尽感／単純作業化の有無を確認。改善して公開。

## 10. 受け入れテスト（自動＋人間）
- T01 視認: 視野外／壁裏ではCHASEに入らない。至近距離では見つかる。
- T02 音: 遮蔽物の向こうの石でINVESTIGATEになっても、その瞬間にプレイヤーの真の位置に向かわない。
- T03 追跡優先: プレイヤーを視認中に石の音が鳴っても、ハンターは視認対象を追う。
- T04 捜索: 遮蔽後、最後の目撃位置と周辺を探索。知らない移動先への自動直行は起こらない。
- T05 潜伏: 草むらで静止し視線を切れば逃げられる場合があるが、視認された直後の近接潜伏は必ずしも安全ではない。
- T06 チェイス: 直線逃走のみでは追いつかれる。板・角・ダッシュで逃走機会が作れる。
- T07 石資源: 2回で空。壁／範囲外への無効投擲でアイテム減少なし。補充2か所・上限2。
- T08 被弾: 1発で確定負けせず、短い再潜伏チャンスがある。HP0で敗北。
- T09 完走: 3台解読→ゲート→成功。残り2台を解読しなくてもよい。
- T10 モバイル: iPhone/iPadで2本指移動＋アクション、石照準・キャンセル、しゃがみ切替、画面回転、入力リセット。
- T11 発見イベント・チュートリアル・進捗UIがゲーム状態に忠実。
- T12 プレイ感: 走るだけで簡単／見つかったら即死の両極を避ける。数試合の観察とユーザーの感想で再調整。

## 11. 反証ポイント・後回し
- 石が強すぎて石→解読の単純作業にならないか。
- SEARCHが賢すぎて視線切りが無効にならないか。
- しゃがみが遅すぎて実際には誰も使わなくならないか。
- ハンターの視界UIで緊張感が消えないか。
- 4ボタンが小画面で過密にならないか。
- ルームやオンライン対戦、複数ハンター、ロッカー追加は**今回のスコープ外**。まず石・しゃがみ・既存草むら・AIの核を完成させる。
